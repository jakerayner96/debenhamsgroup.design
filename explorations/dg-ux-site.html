System / Foundations / Colour

Colour

Primitive ramp per fascia. Values are the signed-off set from the Colour Alignment review (Aug 2026) — switch brands on the dock and the ramp below is the live token output, not a screenshot.

Rendering Debenhams · tokens.css · generated from brands.ts

Semantic mapping

Roles resolve per brand mode: surface/cta/primary → CTA, text/on-cta → On CTA. Dark-primary brands (PLT, boohooMAN) resolve Primary and CTA to the same value; Debenhams keeps CTA as a separate deeper accent.

System / Components / Button

Button

Primary, secondary, disabled and spinner states. The golden-truth state matrix from the Colour Alignment sign-off, rendered from tokens — pick a fascia on the dock.

Rendering Debenhams · packages/components/button · props: variant, state, size

Usage

One primary action per view. Secondary carries the CTA colour as a keyline, never a second fill. PLT renders square with uppercase labels; all other fascias 4px radius, sentence case — this is brand config, not a component fork.

Projects / 2026 / PLP Alignment

PLP Alignment

Status OpenBrief Scott, 01 Sep 26Target w/c 08 SepFascias 5

Align boohoo, boohooMAN, PLT, Warehouse and The Brand Room onto one core PLP template. Differences become configuration — fonts, card toggles, grid, container — not separate builds. PLT is the reference implementation.

Options

A — Strict PLT clone

All five run PLT's exact card and grid; only tokens differ.

B — PLT + per-brand toggles

PLT base; brand label, was-price, badges and grid density configurable per fascia.

C — Density variants

B, plus a compact/comfortable density switch per market.

Options render on this page via the OptionSwitcher once the web PLP build starts — same dock pattern, per-project.
