Jake shared the front-end team's Storybook — `web-storybook.jamesb.play.dbztech.net` (James B's play env) — and asked for three things: ingest all of it and understand how it overlays with ours; a new component set aligned to how the devs build but looking the way we want, published as **our own Storybook ("DG Group Design System")** to hand back to dev; and the site to become a visual wiki of every component (what it is, how to use it — Material / Apple HIG register, not technical). Branch: `plp-alignment` (where the site work already sits).

## 1. Ingest — what the dev build is

Playwright (scraper repo's install) drove the Storybook headless: `index.json` → **79 components · 178 stories**; the preview runtime's story store (`__STORYBOOK_PREVIEW__.extract()`) gave every story's args, argTypes (with the devs' own prop descriptions) and parameters; the 414 KB compiled Tailwind sheet and the per-fascia theme variables were pulled for **all 21 fascias**; every story shot at 1440 + 390 (Debenhams) and 33 key stories in our other six fascias, with DOM + computed-style dumps. Banked in `.context/inventory/storybook-capture/` (index, themes, manifest tracked; 51 MB of shots/dom/extract gitignored) and written up as **`.context/inventory/05-dev-storybook.md`** (architecture, theme-var table, token map, overlay, every component's props).

Facts that matter:
- **React + Tailwind.** `variant` props select class strings (Button has 19 variants). Theming is a flat list of **~25–67 CSS variables per fascia, RGB triplets** (`--color-primary: 123 231 216`) read by utilities (`bg-primary`, `font-cta`, `text-cta`, `rounded` → `--default-rounding`). Greys are fixed utilities on **our exact Grey 1–6 ramp**. `--default-rounding: 0` on PLT and The Brand Room = our square modes. Fonts match ours except KM (Work Sans CTA/heading in dev) and Warehouse (Roboto).
- **Debenhams dev primary is #7BE7D8 with black label** — identical to our signed-off primary; `--color-cta-primary` #00787D is our link/check/focus teal. Disagreements: boohoo primary #444 (ours black), KM primary black (ours #D24508), dev secondary outline grey #B5B5B5 on every fascia (ours brand outline), `--color-text-secondary` #767676 Grey 4 (ours Grey 5 for AA), footer help band peach #FFF1E8 on every fascia. KM/TBR `--color-primary-nav` is malformed (`255 15 NaN`).
- Fascia global key is `fascia`; values `debenhams · debenhamsoutlet · wallis · burton · principles · boohooman · boohooww · karenmillen · prettylittlething · coast · oasis · dorothy-perkins · maine · gorgeous · warehouse · misspap · nastygal · foreverunique · dsgnstudio · trainingdept · thebrandroom`.

## 2. One catalogue, three outputs — `assets/ds/catalogue.js`

New single source: **49 components / 93 variants** as plain HTML on our `components.css` classes, each with summary · when to use · avoid · anatomy · CSS class · Figma node · **dev counterpart + status** (`match` 27 · `partial` 20 · `ours` 18 with no dev counterpart · dev-only/infra 32). Also `DG_DEV_OVERLAY` (all 79 dev titles → ours), `DG_TOKEN_MAP` (29 dev variables → our tokens) and `DG_FASCIA_MAP`. Groups by job: Actions · Forms · Feedback · Product · PDP modules · Navigation · Overlays & bag · Chips & pills · Account · Layout.

- **Site (index.html):** new **Component library** page (`#gallery`) — filterable tile grid, every tile a live render scaled to fit, in the FAB-selected brand; **49 wiki pages** (`#c-<slug>`) generated at load — hero canvas, all variants with an HTML toggle, "In the dev build" box linking the dev story, side rail with When to use / Avoid / Anatomy / Source, prev/next; **Dev alignment** page (`#dev-overlay`) — stat strip, how the devs build, the full overlay matrix and token map. All registered in ⌘K search. Sidebar: the flat component links collapsed into Component library + Dev alignment (old spec pages C-01…C-18 stay, linked from each wiki page as "Full spec"). Demo links inside canvases are inert.
- **Our Storybook (`storybook/`):** Storybook 8.6, HTML renderer on Vite. `gen-stories.mjs` writes `stories/DG/<Group>/<Name>.stories.js` from the catalogue (autodocs; Docs description = the wiki text + dev counterpart link). `preview.js` loads tokens.css + components.css, exposes the **same `fascia` toolbar global** mapped onto `data-brand`. `Introduction.mdx` carries the overlay + token tables. Built clean (`npm run build-storybook` → `storybook-static/`, gitignored, ~7 MB). `node_modules`, `stories/`, `storybook-static/` are not committed.
- Icons fixed in the catalogue: the lib has `icons-notification` (bell) and `icons-down-arrow` (chevron) — the old spec markup's `icons-bell`/`icons-chevron-down` 404 silently via `onerror`.

## 3. The alignment plan (as written on the Dev alignment page)
Our catalogue is the visual target. **match** → dev adopts our tokens/states; **partial** → the note says which states to add on which side (e.g. CartLineItemV2Card has 23 dev states, our bag item draws the base; our sheet is bottom-anchored, dev Side Panel is side-anchored — one shell with an anchor prop); **ours** → new dev component built from our story (checkbox, radio, toggle, toast, empty state, badges, AI strip, size selector, sort & filter, payment buttons, promo field, breadcrumb, chips, Deliver+…); **dev-only** → mostly CMS/content (blog family, hero, marquee, content grid) and bag sections (free gifts, replenishment, samples) for us to spec later. Token intent: the dev theme file gains our semantic names rather than either side re-skinning by hand.
