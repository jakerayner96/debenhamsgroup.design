## What went wrong (so it doesn't again)
- PLT new checkout was built with Debenhams greys/whites hard-coded (`#FAFAFA` bands, `#FFF` sections, white keylined payment tiles).
- The Royalty status pill hard-coded `border-radius:100px` and `#F2F2F2`, so it was round and grey on a square, sand fascia.
- PLT PDP (live recreation) hard-coded `#fff` on size buttons, the USP / returns box, BNPL box, wishlist, reviews button and footer input.
- Change buttons / Discounts / summary links fell back to ink instead of garnet.

## Rules now in the DS
- **PLT sand rule, written out** in the PLT block of `assets/ds/tokens.css` and in `.context/07-foundations.md` §3: no pure white on PLT. Warm white `#FFFDF7` (`--surface-page` / `--surface-raised` / `--panel-bg`) or sand `#FAF5E7` (`--surface-media` / `--surface-sunken`). Never hard-code `#FFF` / `#F2F2F2` / `#FAFAFA` in components.
- **PLT checkout:** gaps + bag bar + order summary `#FAF5E7`; sections `#FFFDF7`; payment tiles + promo Apply sand fill, no outline; promo input `#FFFDF7` with `#B5B5B5` keyline; Change / Discounts / links garnet `--text-link` (#550503).
- **Square means every rounded thing:** pills, chips and status pills take `--radius-pill` (0 on PLT / Brand Room). Only true circles (dots, swatches, avatars) stay round.
