## What this repo is
The Debenhams Group UX site: design system docs, project archive (options + chosen routes), brand centre, requests board — plus (incoming) the master prototypes for core pages. **`index.html` IS the site** — single file, no build step, dark by default with a light theme, sidebar-driven — and since 01 Sep it carries the design system layer itself: canonical tokens (invariant semantic layer + five live fascia modes on `data-brand`), foundations pages (colour, typography, spacing, radius, borders, motion, accessibility), component specs, brand centre with real logo marks. Serve it with `python3 -m http.server 3000` from the repo root (assets need HTTP, not file://).

- **`assets/ds/catalogue.js`** — the component catalogue: one entry per component (HTML variants on `components.css`, when to use / avoid / anatomy, matching dev-Storybook component + status). Renders the site's Component library + 49 wiki pages + Dev alignment page, and generates **`storybook/`** (our DG Group Design System Storybook — `cd storybook && npm run gen|storybook|build-storybook`; `stories/`, `node_modules/`, `storybook-static/` are gitignored). Add components there, never in `storybook/stories/`.
- **`.context/inventory/05-dev-storybook.md`** — the front-end Storybook (web-storybook.jamesb.play.dbztech.net) read end to end: React + Tailwind, per-fascia RGB CSS variables, 79 components with props, token map, overlay.
- **`assets/brands/`** — fascia logo SVGs, named by `data-brand` slug (no dashes: `boohooman`, `karenmillen`, `dorothyperkins`, `brandroom`…). Group lockups are `debenhamsgroup*.svg`. ## Git & session workflow

- **Remote:** `origin → https://github.com/jakerayner96/debenhamsgroup.design.git`. Auth is the Mac's keychain (osxkeychain) — on Jake's machine, plain `git pull` / `git push` just work. A session on any other machine/environment must authenticate to GitHub once first (`gh auth login` or a PAT); a chat-only session can read the public repo but cannot push.
- **Start of session:** `git pull`, check `git branch --show-current` — briefs live on their own branch, site/DS work happens on `main`.
- **New brief:** branch from main named for the project (`plp-alignment` pattern) → `projects/<name>/README.md` (brief, Figma source, decisions) + prototypes that link `../../assets/ds/tokens.css` + `components.css`. Add the branch link to the project's page on the site.
- **Merge = promote:** when a brief's winner merges to main, move its reusable patterns into `assets/ds/components.css`, land any new token facts in `assets/ds/tokens.css`, and spec the component on the site. The branch is never deleted — it's the record.
- **Never force-push.** Commit messages: what + why, ending `Co-Authored-By: Claude <the model> <noreply@anthropic.com>`.
- **End of session:** decisions and state go into a `.context/` session log (next number), and CLAUDE.md's pointer updates to it. Chat history is disposable; the repo is not.

## Rules that always apply
- **Design system only — every project, every chat (16 Oct 2026).** Build from DS components only: tokens.css, components.css, catalogue.js markup, the DS drop-ins (header.js, footer.js, usp.js, taggstar.js, membership.js, bag-summary.js). Never fork or restyle a DS class in a project. Wrong component → fix it here and push; missing component → add it here first (components.css + a catalogue.js entry) and tell Jake by name. **Every DS change gets an entry at the top of `assets/ds/changelog.js`** (site page #changelog): added / changed / fixed / by (project). **The PDP template is the latest PDP (16 Oct 2026) — master = the Shopping agent PDP:** every PDP has Add to bag → PayPal → Apple Pay stacked (`.pdp-ctas`), the delivery grid (`delivery.js`), and the Google prompts + accordion set under the buy column (`.ai-prompts`, `.acc-set`). A new PDP feature lands in `templates/pdp.html` itself so the next PDP pulls it in; a "PDP with X" request starts from the template as it stands, unless Jake says otherwise. In-situ pages use the DS templates: PLP `projects/plp-alignment/plp.html?brand=&mode=new`, PDP `templates/pdp.html?brand=`, Bag `templates/bag.html?brand=`. Same rule in `~/.claude/CLAUDE.md`.
- **The Brand Room has no Deliver+ (22 Oct 2026).** No Deliver+ PDP banner, bag add-on, checkout banner or account banner on Brand Room, in any page or prototype. Gate every Deliver+ piece on `DG_hasDplus(brand)` (`assets/ds/dplus-logos.js`, list `DG_DPLUS_NONE`).
- **PLT: sand, never white; square, never round.** Every surface on PLT is warm white `#FFFDF7` or sand `#FAF5E7` via the surface tokens — never hard-code `#FFF` / `#F2F2F2` / `#FAFAFA`. Pills, chips and status pills use `--radius-pill` (0 on PLT) — never hard-code 100px / 99px. Links, Change buttons and the Royalty dot are garnet `--brand-primary`. Full rule in the PLT block of `assets/ds/tokens.css`; log 33.
- **Spacing is measured in gaps** — 1 gap = 4px = Tailwind spacing unit 1, so gap N = N × 4px = `p-N` / `gap-N` / `m-N`. Quote every spacing value as both: "gap 4 (16px)". Tokens `--gap-N` (tokens.css), Tailwind preset `assets/ds/tailwind.preset.js`; sizes and type stay in px. Spec: `.context/07-foundations.md` §2.
- **Prototypes use the standard review shell** — fascia chips · Desktop/Mobile · width preset · Full page/Fold · Export (zip: 390 + 1440 full-page PNGs) on top, page configuration on the left, resizable frame. Use the `review-prototype` skill (`~/.claude/skills/review-prototype/`, templates inside); references: core-pdp-2026 and `projects/usp-banner/`.
- **"Implement the USP banners" = drop in the DS component, exactly as `projects/usp-banner/`:** load `assets/ds/tokens.css` + `components.css` + `usp-live.js` + `usp.js` (from another repo, link them from `https://jakerayner96.github.io/debenhamsgroup.design/assets/ds/` — older DS snapshots lack the row styles), set `html[data-brand]`, and put `<div data-usp-banners></div>` under the header nav (plus `<div data-usp-banners data-usp-pos="above"></div>` above the logo row if a row sits above). Options: `data-usp-caveats="on"` (off by default), `data-usp-auto="0–5"`. Countdown digits: black on light bars; white or red on black bars, set per row (`cd`). Don't hand-build bars. Refresh the live content by re-scraping each fascia's header into `assets/ds/usp-live.js` (rules in its header comment and the USP banner catalogue entry).
- **Code first, Figma downstream.** Production is canonical; the Figma library mirrors it.
- **Ship fast over perfect.** Jake pushes back on over-engineering and over-clarification. "Go" means proceed; make judgment calls, state assumptions, execute to a defined endpoint.
- **Single-file HTML prototypes, no build step** is the house style for options and reviews. Only the eventual production site gets a real build.
- **Every project records its Figma source** (file key + node id) in its README/page.
- **One repo, branches as briefs**: main = master prototypes; brief → branch → options (OptionSwitcher) → review → merge winner → branch archived as the record.
- **Token provenance**: Figma → plt-app-prototype `src/theme/brands.ts` → `extract-tokens.mjs` → tokens.css. Extend that chain, don't fork it. Signed-off colour truth = colour-alignment-prototype (post-KM review, Aug 26).
- Assets/binaries don't live in git — cloud storage + manifest.
